### 命令介绍  
`git reset` 用于将当前分支的 HEAD 指针重置到指定提交，并可选地修改暂存区（索引）和工作区。它是撤销提交、取消暂存、清理修改的核心命令，不同参数决定了重置的范围。

---

### 参数

#### 重置模式（三选一）
- **`--soft`**  
  仅移动 HEAD 指向指定提交，**不修改**暂存区和工作区。保留所有已暂存和未暂存的修改，适合撤销提交但保留修改内容。
- **`--mixed`**（默认模式）  
  移动 HEAD 并重置暂存区到指定提交，**不修改**工作区。即取消暂存（unstage）所有修改，但保留工作区的变动。适合撤销 `git add` 或取消暂存。
- **`--hard`**  
  移动 HEAD、重置暂存区**并**覆盖工作区到指定提交的状态。**危险操作**，会丢弃所有未提交的修改（包括未跟踪文件需额外清理）。

#### 指定重置目标
- **`<commit>`**  
  重置到指定的提交哈希（如 `HEAD~3`、`abc123`）或引用（如分支名）。省略时默认重置到 `HEAD`（通常用于撤销暂存）。
- **`HEAD~n`**（或 `^`）  
  重置到当前提交之前的第 n 个父提交（如 `git reset HEAD~2` 回退两个版本）。

#### 安全重置
- **`--merge`**  
  重置到指定提交，但保留工作区中**未暂存**的修改，并丢弃暂存区的修改。若重置路径与工作区修改冲突，则取消操作，防止丢失变更。
- **`--keep`**  
  重置到指定提交，但保留工作区中**已暂存和未暂存**的修改。若重置路径与工作区修改冲突，则取消操作，适合在保留本地改动的前提下回退。
- **`--no-verify`**  
  跳过重置前的预提交钩子（pre-commit hook）和提交信息钩子（commit-msg hook）。

#### 路径限定（针对特定文件）
- **`<paths>`**（如 `git reset HEAD -- file.txt`）  
  将指定文件在暂存区的状态重置为指定提交时的版本（不影响 HEAD 位置），常用于取消暂存特定文件。`--` 用于分隔提交与文件路径。
- **`--patch`**（或 `-p`）  
  交互式选择重置暂存区中文件的部分块（hunks），允许精细控制哪些修改被暂存或取消暂存。

#### 选项/控制
- **`-q`** / `--quiet`  
  静默模式，不输出重置后的状态信息（除非发生错误）。
- **`--verbose`**（或 `-v`）  
  输出详细信息，显示重置后暂存区与工作区的差异。
- **`--recurse-submodules`**  
  重置子模块到指定提交（与主仓库同步）。

#### 特殊用途
- **`--soft` + `--hard` 等（已在核心模式中列出）**  
- **`--mixed` 是默认**，可省略。
- **`--keep`** 与 **`--merge`** 的区别在于前者保留所有修改，后者仅保留未暂存修改。
- **`--orphan`**（不常用）  
  切换到全新的独立分支，丢弃所有历史（需配合 `git checkout` 等，实际不属 reset 参数）。

---

以上参数可按需组合（如 `git reset --soft HEAD~1` 撤销上次提交保留修改）。若需某参数的具体示例或场景，可随时追问。
